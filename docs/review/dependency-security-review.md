# 依存パッケージの既知脆弱性確認

作成日：2026年8月24日

## 1. この文書の目的

この文書は、ConnLogの少人数テストユーザー招待前に、依存パッケージの既知脆弱性を確認し、更新内容と残るリスクの判断根拠を記録するものである。

脆弱性の対応要否は、`npm audit`に表示される重大度だけでは判断せず、次の点を含めて確認する。

- 該当するパッケージとバージョン
- Productionで使用される依存関係か
- ConnLogから該当機能へ到達できるか
- 安全に適用できる更新が存在するか
- 更新によって互換性を壊す可能性がないか

## 2. 確認条件

- 確認日：2026年8月24日
- ローカルNode.js：`v21.5.0`
- パッケージ管理：npmおよび`package-lock.json`
- 確認コマンド：`npm audit`、`npm audit --omit=dev`、`npm ls`
- 確認対象：Production依存、開発依存、アプリケーションからの利用経路
- 破壊的変更を伴う`npm audit fix --force`は実行しない

## 3. 適用した更新

安全に適用できる範囲で、次の更新を行った。

| 対象 | 更新前 | 更新後 | 判断 |
| --- | --- | --- | --- |
| Next.js | `15.5.22` | `15.5.23` | 同じ15.5系のパッチ更新 |
| eslint-config-next | `15.5.22` | `15.5.23` | Next.jsとバージョンを統一 |
| nanoid | `3.3.11` | `3.3.18` | 既知脆弱性の修正版へ更新 |
| Tailwind側PostCSS | `8.5.6` | `8.5.26` | 既知脆弱性の修正版へ更新 |
| sharp | `0.34.3` | `0.34.5` | Next.js 15の許容範囲内で更新 |

さらに、通常の`npm audit fix`を実行し、ESLintなどの開発用ツールに含まれていた既知脆弱性を、安全に更新可能な範囲で解消した。

`package.json`の直接依存に追加されたパッケージはなく、直接の変更はNext.jsと`eslint-config-next`のパッチ更新だけである。


## 4. 更新後の`npm audit`結果

更新後に`npm audit`と`npm audit --omit=dev`を実行したところ、どちらも3件のHighが残った。

残っている報告は、Next.js 15.5.23が内部で使用する次の依存関係に由来する。

| パッケージ | 使用中のバージョン | `npm audit`の報告 |
| --- | --- | --- |
| PostCSS | `8.4.31` | CSSの文字列化やsource mapの処理に関する複数の既知脆弱性 |
| sharp | `0.34.5` | 内部で使用するlibvipsに由来する既知脆弱性 |

`npm audit`が示す自動修正は、Next.jsを`16.3.2`へ更新するものである。これはメジャーバージョン更新であり、破壊的変更を含む可能性があるため、このタスクでは適用しない。

開発用依存関係に報告されていたCritical・High・Moderate・Lowの問題は、通常の`npm audit fix`後には表示されなくなった。更新後は、通常の`npm audit`とProduction依存だけを対象にした`npm audit --omit=dev`が同じ3件を報告している。

## 5. アプリケーションからの到達可能性

### PostCSS

コード検索では、`src`内にPostCSSまたはnanoidを直接使用する処理は確認されなかった。また、利用者がCSSやsource mapを投稿・アップロードし、サーバー側で処理する機能は実装されていない。

ConnLogにおけるPostCSSは、主に開発時やビルド時のCSS処理で使用される。現在の機能では、攻撃者が用意したCSSやsource mapを該当処理へ渡す経路は確認されなかった。

### sharp

コード検索では、`src`内に`next/image`の使用、ファイル入力、`FormData`、`multipart/form-data`、画像アップロード処理は確認されなかった。

`next.config.ts`にも、外部画像を許可する`images.remotePatterns`や`images.domains`などの画像設定は存在しない。現在の機能では、利用者が用意した画像をNext.jsの画像最適化処理またはsharpへ渡す経路は確認されなかった。

以上は現在のソースコードと設定に基づく到達可能性の判断である。将来、画像アップロード、外部画像表示、利用者が入力したCSSの処理などを追加した場合は、前提が変わるため再確認が必要になる。


## 6. 現時点の判断

安全に適用できるパッチ更新と間接依存の更新により、nanoidと開発用依存関係で報告されていた既知脆弱性は解消した。

一方、Next.js 15.5.23が内部で使用するPostCSSとsharpに由来する3件のHighは残っている。ただし、現在のConnLogには、攻撃者が用意したCSS、source mapまたは画像を該当処理へ渡す機能は確認されていない。

このため、残る3件は既知脆弱性として記録したうえで、少人数の招待制MVPを直ちに中止する理由にはならないと判断する。この判断は脆弱性が存在しないという意味ではなく、現在の機能と利用経路では攻撃成立に必要な入力経路が確認されていないことに基づく。

Next.js 16への更新は、メジャーバージョン変更として別タスクで互換性を確認しながら実施する。次のいずれかに該当した場合は、この判断を再確認する。

- Next.js 15向けに該当依存関係の修正版が提供された場合
- Next.js 16への移行を行う場合
- 画像アップロードまたは外部画像の最適化機能を追加する場合
- 利用者が入力したCSSまたはsource mapを処理する機能を追加する場合
- 新たな脆弱性情報により、現在の到達可能性に関係なく影響を受けると判明した場合

## 7. 検証結果

依存関係の更新後に、次の確認を実施した。

| 確認項目 | 結果 |
| --- | --- |
| `git diff --check` | 問題なし |
| `npm run lint` | エラーなし |
| `npm run build` | Next.js 15.5.23で成功 |
| 型検査 | 成功 |
| 静的ページ生成 | 24ページすべて成功 |
| `npm audit` | 3件のHighが残存 |
| `npm audit --omit=dev` | 同じ3件のHighが残存 |

残る3件については第5節の到達可能性を確認し、第6節のとおり現時点では限定的に許容する。`npm audit fix --force`は実行していない。
